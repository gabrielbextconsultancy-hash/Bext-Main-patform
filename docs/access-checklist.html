How it connects

2.4 Teams application access policy Blocked — action required

Verified error: 403 — No application access policy found for this app b72d1df4-06ec-4390-937a-1293f34d31be on the user
Why it exists
Separate from consent by design. A tenant-wide transcript permission would otherwise let the application read every meeting in the organisation, so Microsoft requires an administrator to name which users an application may read. Consent alone always returns 403 — this is not a misconfiguration.
Where
PowerShell only. There is no portal page and no Graph API for it — the sole interface is the MicrosoftTeams PowerShell module, signed in as a Teams administrator.
Commands (run by Brent, once)
Install-Module MicrosoftTeams -Scope CurrentUser -Force -AllowClobber
Connect-MicrosoftTeams -AccountId Brent@bextconsultancy.com.au
New-CsApplicationAccessPolicy -Identity BEXT-Automation-Policy -AppIds "b72d1df4-06ec-4390-937a-1293f34d31be" -Description "BEXT Automation transcript access"
Grant-CsApplicationAccessPolicy -PolicyName BEXT-Automation-Policy -Identity Admin.bext-automation@bextconsultancy.com.au
Scripted and idempotent at graph/teams-access-policy.ps1. Allow up to 30 minutes to take effect.
Reference
Application access policy — Microsoft Learn · List transcripts API
Blocks
The entire meeting workflow: transcript retrieval, minutes generation, action extraction, follow-up drafts. Brief B review area 3 — the client's stated highest priority.

2.5 Transcript API access — tenant control Blocked — action required

Verified error: 403 — Graph API access to transcripts is disabled for this tenant.
Why it exists
A tenant-wide control Microsoft introduced in late July 2026, enforced from 31 July — after this engagement was scoped. It is off by default, and it is a fourth, independent gate: consent, the application access policy and the transcription toggle can all be correct and transcripts still return 403 until this is switched on. There is no request-side workaround.
Where
Teams admin center → Meetings → Meeting settings → Transcript API access → Microsoft Graph access: On. Then Configure beside it → Include speaker attribution: On.
Link: admin.teams.microsoft.com/meetings/settings
Speaker attribution is not optional here
Without it the transcript carries no names. Minutes could summarise what was said but could not attribute decisions or assign action items to a person — which is most of what the brief asks for.
Reference
Get callTranscript — Microsoft Learn
Propagation: typically 30–60 minutes, occasionally longer.

2.6 Policy scope — whose meetings can be read Partial

Verified error on meetings organised by others: 403 — 3003: User does not have access to lookup meeting
The access policy authorises the application against the users it is granted to. Granted only to Admin.bext-automation@, it cannot read meetings organised by Brent — which in practice is most of them.
Fix — grant tenant-wide
Grant-CsApplicationAccessPolicy -PolicyName BEXT-Automation-Policy -Global
Tenant-wide is proportionate here: the alternative is granting each organiser individually and repeating it for every person added later. The application remains limited to the ten consented permissions — this decides only whose meetings it may read.

2.7 Teams Administrator role Recommended

Where: Entra admin center → Users → Admin.bext-automation → Assigned roles → Add assignments → Teams Administrator
Link: entra.microsoft.com → Users
Why
The service account currently holds no directory roles, which is why the Teams admin center returns INVALID_PRIVILEGE and why every Teams task has to be escalated to Brent. Teams Administrator is sufficient for meeting and application policies and does not give a service account control of the tenant — deliberately not Global Administrator.

4. Third-party platforms

4.1 HubSpot Partial — scope missing

Verified: contacts and deals return 200. Companies returns 403 — This app hasn't been granted all required scopes to make this call.
Portal: HubSpot → Settings (gear) → Integrations → Private Apps → the app → Scopes tab → add crm.objects.companies.read (and .write if the automation should create records) → Save → the token stays valid.
Link: app.hubspot.com/private-apps · Portal ID 443333225
How it connects
Companies is how any workflow answers "which client is this?" — the lookup behind filing a document to the right folder, matching a meeting to an engagement, and addressing a client update. Contacts and deals alone cannot resolve that.
Reference
Companies API · Scopes reference
Also outstanding: the portal holds 1 sample deal and 0 companies. Until real data exists, client matching has nothing to match against.
