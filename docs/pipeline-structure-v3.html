2 · Hourly ingestion — how a source is actually fetched

One rule governs the ladder: the cheapest tier that demonstrably works, verified by evidence, visible when it fails. Every tier writes an attempt row every run — tried, skipped, succeeded, refused — so "was this even attempted?" is always answerable. That log is what caught every silent failure this week.

4 · News Quality — the three-stage pass (06:00 / 12:00 / 23:00)

StageWhat it doesGuard rails
EnrichOpens articles still undated, reads the publisher's own date, writes published_at + date_statePer-host politeness · 4-min budget · a resolved date older than 14 days holds the article automatically (archive can never masquerade as news — 484 caught once)
JudgeHermes separates news from standing pages (DWGM, ISP, "IT change & release management")Batches of five (larger drifts out of format) · undecided ships · verdict stored, judged once
MonitorWrites the coverage line to integration_health — the number to quote when asked "how many articles were affected"Counts the Self-Heal blind spot: sources that ran clean and returned zero
The 23:00 pass is the reconciliation gate. The original design placed a catch-up step inside the 05:00 report; it was deliberately moved out — the send is the client deliverable, and a diagnostic that throws must not take it down (four consecutive runs were once lost that way). The 23:00 pass completes the day before it closes, so 05:00 reads finished data instead of racing it; the widened window + ledger make the gate unnecessary on the send path itself.

5 · The report — four gates, then send

window: real publication date, day-2 → now (drift-proof) minus everything already sent (ledger — exactly once) gate 1 relevance ≥ 1 noise kept, wrong-subject dropped (score 0 stays in the data) gate 2 not a reference page (judge verdict) gate 3 not furniture (no date AND score 0 — never was an article) gate 4 not stale-dated (report_eligible hold) → render → Microsoft Graph send (token as urlencoded form; non-202 THROWS) → report row 'sent' only on a real 202 — a failed send can never look successful

7 · Verification — how the system is checked, continuously

  • Preflight (n8n/preflight.js) — 30+ regression assertions before any deploy; every rule cites a documented regression.
  • Contract Test — nightly 02:00: every scheduled workflow has an unconditional heartbeat, Code nodes parse, inlined libs are stripped of exports.
  • Attempt log — every source × tier × run; 30-day retention; the dashboard tier-strip reads it live.
  • Coverage line — per quality pass; trends the wrong-day number toward zero.
  • Ledger check — already-sent articles can never reappear (0 duplicates verified).
  • Send guard — non-202 throws; both silent-send incidents this week were caught by it, not by a reader.
  • Live watches — first runs of new machinery are monitored to completion, not assumed (Firecrawl's first window, the S&P sitemaps, the quality passes — each caught a real fault this way).
