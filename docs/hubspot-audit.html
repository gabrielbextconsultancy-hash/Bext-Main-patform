1. Executive summary

HubSpot has been deliberately configured but never adopted. That distinction matters, because it changes the recommendation entirely.

Someone invested real design effort: eight custom properties were created across contacts and deals, modelling exactly the things an energy consultancy needs to track — service type, billing model, expected outcome, engagement start date. A six-stage sales pipeline was defined and named sensibly. This is not an untouched trial account.

But there is no data behind any of it. One deal exists, and it is the sample record HubSpot creates automatically at signup. No companies. Four contacts, none linked to a company, none created since 11 June 2026.

Correction to the Draft Plan. The draft plan names HubSpot the source of truth for clients and contacts. On the evidence it is not currently a source of anything. The schema shows the intent was sound — the gap is adoption, not design.

The companies denial blocks the onboarding automation as designed. A client onboarding flow that creates a contact but cannot create or associate the company produces orphaned records — which is precisely the state the CRM is in today. Add crm.objects.companies.read and crm.objects.companies.write to the private app before building it.

8. Recommendations

Immediate — before any build

  • Correct the portal time zone to Australia/Melbourne and currency to AUD. Cheap now, disruptive after deals exist.
  • Widen the private app scopes to include companies read/write and owners read. Without companies the onboarding flow cannot produce complete records.
  • Delete the sample deal so reporting starts from a true zero.

Structural — the decision for 25 August

Three options, and the integration diagram differs materially between them:

  • Adopt. Backfill companies and deals from the 18 ProjectManager projects, then run onboarding through HubSpot as the draft plan describes. The custom schema already supports this; the work is a one-off migration plus the scope fix.
  • Demote. ProjectManager holds the client relationship, HubSpot is retired, and the architecture loses a platform. Lowest ongoing effort, and it forfeits the pipeline visibility that the stage design was clearly built for.
  • Leave as-is. Not recommended. Documenting an unused CRM as a source of truth would make the architecture describe something that is not happening.

On the evidence — a considered custom schema and a well-formed pipeline — adopt is the stronger option. The design work has already been done; what is missing is the data and the two scope changes.

9. Method

Measured on 7 August 2026 against the HubSpot REST API v3 using the private app token stored as HUBSPOT_TOKEN. Counts reflect the first page of each collection; contacts, companies, deals and tickets all fit within one page, so those figures are complete. Endpoints returning a scope error are recorded as denied rather than empty — the distinction matters, since a denied companies endpoint and zero companies look identical from outside.
