What this is

As part of the Business Structure Efficiency work, an application has been registered in your Microsoft 365 tenant called BEXT Automation (Dev). It is the account the automation uses to read and write on the business's behalf — producing meeting minutes from Teams recordings, drafting emails in Outlook, and filing documents into SharePoint.

The application has been created and its permissions attached. It cannot do anything yet. Microsoft requires that a Global Administrator approve the permissions before they take effect. That approval is the only outstanding step, and it can only be done by you — the automation account deliberately does not have the authority to approve its own access.

Why you and not the developer. Microsoft separates creating an application from approving what it can reach. Anyone can register an app; only an administrator can grant it access to organisational data. That separation is a safety feature, and it is working as intended here.

Be aware of what you are agreeing to. These are tenant-wide permissions. They are not limited to one mailbox or one site — the application will technically be able to reach any mailbox, any SharePoint site and any file in the tenant. That is how Microsoft's application permissions work; there is no narrower option that still allows unattended automation.

This is appropriate for a development tenant with one user. Before this moves to production, the developer has committed to scoping Mail.Send down with an application access policy so it can only send from the one mailbox it needs. Ask for that to be confirmed at handover.

Step 3. A Microsoft page will appear headed “Permissions requested” showing BEXT Automation (Dev) and the list of nine permissions above. Read them, then click Accept.
Step 4. The browser will attempt to redirect afterwards and may land on an error page, or a page that will not load. This is normal and does not mean it failed. The application has no website to return you to. The approval is recorded the moment you click Accept.
Step 5. Let Gabriel know it is done. He will confirm it worked within a minute by running a verification check that requests a token, reads a user, and sends a single test email.

If something does not look right

  • The page says you need an administrator — you are signed in as an account without the Global Administrator role. Sign out and use one of the two accounts named in Step 1.
  • The app name is not “BEXT Automation (Dev)” — stop and check with Gabriel before accepting. You should only approve an application you were expecting.
  • You see more or fewer than nine permissions — stop and check. The list above is exactly what was requested.

Undoing it later

This is fully reversible and does not require the developer. In the Microsoft Entra admin centre → Enterprise applications → BEXT Automation (Dev), you can review the granted permissions at any time, or delete the application outright, which immediately revokes all of its access.

Nothing is blocked while you decide. The daily industry report is already running and delivering by a separate email route. This approval unlocks the meeting, email and document workflows — the highest-value parts of the brief — but the rest of the work continues either way.
